Описание: Панель действий (Action Panel)

Расположение
- Панель фиксируется внизу экрана по центру и содержит 4 круглые кнопки: `Действие`, `Бонусное действие`, `Реакция`, `Закончить круг`.

Используемые CSS-классы
- `.action-panel` — контейнер панели.
- `.action-btn` — кнопка в виде круга.
- `.action-circle` — визуальный круг внутри кнопки (цвета: `.action-primary`, `.action-bonus`, `.action-reaction`, `.action-end`).
- `.action-label` — подпись под кнопкой.
- `.used` — класс, который помечает кнопку как использованную (серое/неактивное состояние).
- Модальное окно: `.action-modal-overlay`, `.action-modal`, `.action-option`.

Логика (файл `js/action-panel.js`)
- Инициализация: при `DOMContentLoaded` регистрируются обработчики кликов по кнопкам и кнопке `Закончить круг`.
- Открытие модалки: при клике по `Действие/Бонус/Реакция` открывается модальное окно со списком опций.
  - Источники опций:
    - базовые действия (жёстко закодированные в `basicActions`);
    - персональные атаки из `state.attacks`;
    - заклинания из `state.spells` (показываются как опции, но ячейки не списываются автоматически);
    - доступные классовые ресурсы из `state.classResources` (если `current>0`).
- Выбор действия: при выборе опции вызывается `handleActionSelected(type, opt)` — опция логируется (`addToLog`) и кнопка помечается как использованная (`setButtonUsed`).
- Визуал: текст выбранного действия показывается внутри круга (урезается при длине).

Классовая логика и временные дополнительные действия
- Хуки для простых правил:
  - `fighter` — если у воина есть ресурс `Всплеск действий` (`state.classResources.fighter.current > 0`) и выбран пункт `Action Surge`, ресурс уменьшается и даётся временное дополнительное действие: `state._tempExtra = { type: 'action', remaining: 1 }`.
  - `paladin` — если первым действием было `attack`, устанавливается `state._tempExtra` для `action`, что позволяет совершить дополнительную атаку (метод `checkClassTriggers`).
- `state._tempExtra` служит для временного восстановления доступности кнопки (не постоянного сброса).

Персистентность
- Текущее визуальное состояние кнопок сохраняется в `state.actionPanel` (объект по типам `action`, `bonus`, `reaction` с полем `used` и `label`).

API
- `window.actionPanelAPI.init()` — инициализация (вызывается автоматически).
- `window.actionPanelAPI.setUsed(type, label)` — программно пометить кнопку как использованную.
- `window.actionPanelAPI.reset()` — сброс всех кнопок.
- `window.actionPanelAPI.isAvailable(type)` — проверка доступности кнопки.

Как дорабатывать
- Списание слотов заклинаний: добавить логику в `handleActionSelected` при выборе `opt.source === 'spell'` (использовать `state.spellSlots` / `renderSlots`).
- Поддержка сложных условий классов (многократные атаки, реакции с ограничениями) — реализовать набор «правил» в отдельном модуле и вызывать их в `checkClassTriggers`.
- Иконки: вместо текста внутри круга можно отображать SVG-иконки — поменять содержимое `.action-circle`.

Тестирование локально
1. Откройте `index.html` в браузере (или запустите локальный сервер).
2. Кликните по кнопкам панели и проверьте, что модалка показывает варианты: базовые, атаки и заклинания.
3. Выберите опцию — должны поменяться визуальные состояния кнопки и появиться запись в журнале (`logArea`).
4. Нажмите `Закончить круг` — все кнопки должны сброситься.

Заметки
- Текущая реализация фокусируется на UX и расширяемости; бизнес-правила (полная симуляция боевого хода и списание ресурсов) оставлены для дальнейшей доработки по требованиям.
